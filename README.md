# BishopTech iOS 26 Skills Lab

> Turn an LLM into a disciplined Apple-native engineering team.

An official-source-grounded knowledge base and open-source-ready skill bundle for building high-quality iOS apps with Swift, SwiftUI, Liquid Glass, Apple Intelligence, on-device AI, and the wider Apple SDK.

The goal is ambitious: give a solo developer the practical coverage of an architect, native UI designer, AI engineer, implementer, test engineer, accessibility auditor, security reviewer, release manager, and documentation maintainer—while keeping every claim tied to the right Apple source, target, device, and evidence level.

## Project snapshot

- **1,007** source-linked Markdown files
- **976** content pages
- **3,081** distinct official Apple/Swift destinations
- **19** validated role-oriented skill packages
- **19** portable skill artifacts
- Dedicated routes for SwiftUI, Liquid Glass, on-device intelligence, testing, accessibility, privacy, security, physical devices, and release evidence

This is an active research and engineering system, not a promise of App Store approval. A compile, preview, simulator run, model response, archive, or TestFlight upload is never treated as universal proof of production behavior.

## What makes this different

Most AI coding guidance jumps from an idea to a code snippet. This project routes the work through the constraints that make Apple-native software real:

- capability and framework selection before implementation;
- target, SDK, deployment, device, entitlement, permission, and extension gates;
- native SwiftUI composition and functional Liquid Glass instead of cosmetic blur;
- typed, reviewable, privacy-aware on-device AI proposals with deterministic commit boundaries;
- accessibility, Dynamic Type, reduced motion/effects, alternate input, and system-surface review;
- Swift Testing, XCTest, UI automation, performance, physical-device, two-device, archive, TestFlight, and production evidence;
- source refresh and availability maintenance when Apple documentation or SDK interfaces change.

## What this is and is not

This is a source-linked synthesis of official Apple and Swift documentation. It paraphrases platform guidance, links to the source page, and adds implementation routing and verification questions. It is not a replacement for SDK headers, Xcode diagnostics, Human Interface Guidelines, current Apple Developer documentation, legal advice, or actual device/App Store/production evidence.

The knowledge base and skills are open-source-oriented and review-ready, but they do not claim guaranteed Apple approval. Apple platform behavior, availability, entitlements, policies, and hardware support can change; refresh the cited source and installed SDK before relying on a version-sensitive route.

## Source discipline

- Technical claims link to `developer.apple.com` or `docs.swift.org`.
- Availability is recorded as a question to verify, not assumed from a remembered API name.
- “Runs in the simulator,” “works on a signed device,” “passes review,” and “works in production” are separate claims.
- Apple-like polish means using system components, semantic typography, accessibility, and platform behaviors—not copying proprietary screens or branding.
- Privacy manifests, required-reason APIs, test plans, performance diagnostics, accessibility audits, signed artifacts, TestFlight, and production behavior are separate evidence records; none is silently substituted for another.
