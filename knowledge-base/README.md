# iOS 26 Knowledge Base

## How to use this library

For a requirement-level view of what the first tranche covers and what remains future expansion, read the [coverage matrix](coverage-matrix.md).

Start with the outcome you want to build, then follow the route:

`idea -> capability -> framework -> state/data -> UI -> system surface -> verification`

For example, “a private app that scans a receipt, extracts fields, lets the user correct them, and reminds them later” routes through VisionKit or PhotosUI, Vision OCR, a reviewable domain model, SwiftUI forms, SwiftData, UserNotifications, and device/permission testing.

## Status markers

Each module should make these things easy to find:

- `Availability`: minimum OS, device, or model-state caveat to verify.
- `Route`: the first framework/API family to investigate.
- `Boundaries`: privacy, permissions, entitlements, or system limits.
- `Proof`: what a preview, simulator, physical device, and release test can actually prove.
- `Sources`: official Apple/Swift links used for the synthesis.
