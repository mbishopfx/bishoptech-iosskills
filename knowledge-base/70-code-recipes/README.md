# Compile-Oriented Code Recipes

These pages are small route sketches for turning the knowledge base into Swift code. They are intentionally narrower than a full app and are not claimed to compile in this documentation-only workspace. Before copying a recipe:

1. Set the deployment target and SDK.
2. Confirm the API’s current signature and availability in Xcode.
3. Add required capabilities, permissions, packages, and assets.
4. Compile the smallest slice.
5. Test the real permission, device, model, entitlement, and lifecycle behavior.

## Proof-first recipe rule

Every recipe must state what preview, fixture, unit test, UI test, simulator, signed physical device, system-surface run, server/account environment, and release build can prove. Keep permission/entitlement, process/extension, model/media readiness, cancellation/backpressure, privacy/retention, accessibility, performance/thermal, and fallback state visible in the route sketch. A code snippet that compiles is not evidence that a protected service, physical sensor, Apple Intelligence model, system surface, or production release behaves as intended.

## Code discipline

Keep secrets out of snippets, make permission gates visible, prefer semantic system controls, and label every untested route. A snippet that compiles can still be wrong for a product if it bypasses authorization, validation, accessibility, or lifecycle behavior.
