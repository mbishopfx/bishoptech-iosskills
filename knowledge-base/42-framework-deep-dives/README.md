# Device, Media, Security, and Spatial Deep Dives

These pages extend the route catalog into hardware-facing and high-sensitivity Apple frameworks. They are organized around product decisions rather than framework trivia:

`user outcome -> device capability -> framework boundary -> permission/entitlement -> state model -> proof`

The same principle applies across this tranche: a health sample is not a diagnosis, a camera frame is not confirmed content, a keychain item is not a server session, and an AR session is not a simulator feature. Keep those boundaries visible in the app architecture and in the user-facing copy.

## Cross-cutting device, input, and proof routes

| Route | Concrete boundary | Minimum evidence |
| --- | --- | --- |
| Camera, motion, and haptics | `AVCaptureSession`, `CMMotionManager`, `CHHapticEngine`, authorization/capability, interruption, teardown, and reduced-effects fallback | Physical device with camera/sensor/haptic hardware, denied/revoked permission, interruption, battery/thermal, and alternate feedback paths. |
| Accessibility and input | SwiftUI semantic controls, `AccessibilityFocusState`, `DynamicTypeSize`, `accessibilityReduceMotion`, VoiceOver/Voice Control/Switch Control, keyboard/controller/pointer input | Task-based physical-device testing with assistive settings; audit output is diagnostic and does not prove reading order, ergonomics, or localization. |
| Performance and diagnostics | XCTest performance metrics, `XCTHitchMetric`, signposts, MetricKit daily metrics/diagnostics, frame/memory/CPU/storage/energy state | Controlled regression baseline plus representative physical-device and release-build observations; do not treat a Debug run or newest device as universal. |
| Release/system proof | target membership, entitlements, privacy strings/manifests, extension/system-surface configuration, signing, TestFlight/App Store metadata, server/APNs/account state | Separate source, compile, simulator, signed device, system surface, sandbox/TestFlight, App Store, and production evidence. |

When a deep dive crosses these routes, keep the framework result separate from the user-facing claim: a sensor reading is not physical truth, an accessibility audit is not an accessible experience, a metric is not a guarantee, and a signed build is not production delivery.
