# Capability Recipes

This folder turns Apple frameworks into reusable app-building patterns. Start with the [idea-to-route worksheet](00-idea-to-route.md), then choose the smallest recipe that matches the user outcome. For target/module/extension composition, continue with the [project, target, module, and extension route matrix](../40-framework-routes/11-project-target-and-extension-route-matrix.md). The recipes are architecture guidance, not compiled app templates.

The focused blueprints below turn newer edge routes into buildable compositions while keeping the user-approved record, device/system state, generated proposal, and side effects separate.

These playbooks compose the core recipes into concrete patterns while keeping the boundaries explicit:

`user outcome -> source/input -> deterministic observation -> optional AI proposal -> review/validation -> domain truth -> system surface -> evidence`

## Selection rule

Prefer the narrowest route that satisfies the outcome. Add a second framework only when its responsibility is clear. Keep UI state, domain truth, generated/model output, external system state, and side effects separate.
